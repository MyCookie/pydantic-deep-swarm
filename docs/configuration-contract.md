## Question

For `init`, `serve`, and `doctor`, what exact precedence and persistence rules govern `--config`, `--state-dir`, `--workspace-dir`, their environment variables, local YAML, and defaults? Specify what happens when an existing YAML path disagrees with an explicit command-line path, when a chosen config file is missing, and when `init` runs repeatedly. The answer must keep mutable state outside the checkout and ensure `init` and `serve` select the same paths, including the handoff's `AGENT_TEAM_STATE_DIR` escape case.

## Resolution

Configuration-file selection and runtime-path selection are separate:

1. Select the config file by `--config`, then `AGENT_TEAM_CONFIG_FILE`, then `<selected-state-dir>/config/config.yaml`. A named file is exact: do not search elsewhere if it is missing. `init` creates a missing named file; `serve` and `doctor` fail clearly. When neither selector names a file and the usual config file is absent, `serve` may use environment/default-only configuration, and `doctor` reports that fallback.
2. Select `state_dir` and `workspace_dir` **per field** by command-line flag, then YAML, then environment, then default. A YAML file that omits one field does not suppress its environment fallback. Treat `workspace_dir: null` as omitted; a null `state_dir` is invalid. `AGENT_TEAM_STATE_DIR` is the primary state environment value; retain `AGENT_TEAM_HOME/.agent-team` as a compatibility fallback, then `~/.agent-team`. The workspace default is `<final-state-dir>/workspace`.
3. A `--state-dir` or `--workspace-dir` flag wins over a conflicting YAML value for that invocation. An explicit YAML workspace remains selected when only the state directory is overridden; report and validate both final paths separately. If a state directory selected through the environment contains YAML pointing to a different state directory, fail instead of silently escaping to the YAML path.
4. Resolve relative flag and environment paths against the invocation directory, and write absolute state and workspace paths into generated YAML. YAML path fields may use the existing `${VAR}` substitution grammar, but their expanded values must be absolute. Resolve paths before comparison and reject state or workspace locations inside the source checkout. `serve` and `doctor` may read a config file inside the checkout; `init` may not create or overwrite one there.
5. `init` creates missing directories, reports the selected config, state, and workspace paths, and preserves an existing config on repeat runs. If an existing config disagrees with or does not persist an explicit `--state-dir` or `--workspace-dir`, `init` fails with an actionable mismatch instead of reporting success. `init --overwrite-config` explicitly replaces the whole selected YAML file, saves a backup of the old file, and writes the replacement atomically. `serve` and `doctor` never rewrite YAML; their flags apply only to that invocation.

These rules prevent the current `init` template from sending a later runtime to `~/.agent-team` after initialization selected another state directory. The terms **State directory** and **Workspace directory** are defined in `CONTEXT.md`; the rationale is recorded in `docs/adr/0001-runtime-configuration-authority.md`.
